# Вопросы Claude на острове — mini-spec

Запрос владельца 2026-11-06 (снимок: в терминале диалог с выбором «Имя сессии / Без журналов», а остров показывает лишь «ждёт разрешения · AskUserQuestion»): «такие моменты можно в topbar показать, а не чтобы перемещался на окно?»

## Что меняем
Когда Claude Code задаёт вопрос с вариантами (`AskUserQuestion`), на острове появляется карточка с этим вопросом и кнопками-вариантами. Нажатие на вариант отвечает Claude: диалог в терминале не открывается, переходить в окно не нужно.

- Заголовок карточки — как у карточки разрешения (имя сессии, под ним проект · ветка · приложение).
- Над вариантами — короткая метка вопроса (`header`) и сам вопрос. Варианты — кнопками; пояснение варианта (`description`) мелко под названием.
- Если вопросов несколько (их до четырёх), они идут по одному, «1 из 2»; ответы уходят Claude разом после последнего.
- Вопрос с множественным выбором: варианты отмечаются, внизу «Готово».
- Слева тихие кнопки как у карточки разрешения: «Открыть в <приложение>» и «Позже» — тогда вопрос остаётся в терминале, как сегодня.
- Ответ «Свой вариант» (свободный текст) в остров не переносим: для него «Открыть в <приложение>».

## Как это работает (проверено)
`AskUserQuestion` приходит хуку `PermissionRequest`. Ответ хука `allow` с `updatedInput`, в который добавлено поле `answers` (текст вопроса → подпись выбранного варианта), Claude принимает как ответ владельца. Опыт 2026-11-06 на Claude Code 2.1.318: хук ответил «Красный», диалога в терминале не появилось, Claude написал «Вы выбрали: красный».

## Зачем
Сессий несколько, терминалы в разных окнах. Вопрос Claude сейчас виден на острове только словом «ждёт»: чтобы ответить, нужно найти нужное окно. Разрешения уже решаются с острова; вопросы остались единственным запросом, который требует перехода в терминал.

## Что НЕ меняем
- `ExitPlanMode` (утверждение плана) — по-прежнему в терминале.
- Карточку разрешения для команд и правок, очередь запросов, статусы.
- Любое сомнение — прежнее поведение (диалог в терминале): вопрос с `preview` у вариантов, больше четырёх вариантов, непонятная форма ввода, приложение не запущено, нет доступа, «Позже».
- Ответы никуда не отправляются и не логируются: они уходят только в Claude Code через мост.

## Влияние на схему БД
Нет. В ядре: у запроса — разобранные вопросы; у ответа моста — необязательное поле `answers` (старые сообщения читаются как раньше). `passthroughTools` теряет `AskUserQuestion` при допустимой форме вопроса.

## Риски
- Формат `answers` для `AskUserQuestion` через `updatedInput` в документации Claude Code описан слабо. Если в новой версии он изменится, остров ответит впустую. Защита: тест на разбор формата и проверочный прогон с живым Claude Code перед выпуском; плохой ответ не страшнее текущего «Позже» (владелец ответит в терминале).
- Формат ответа на вопрос с множественным выбором (варианты через запятую) пока не проверен — проверить опытом до реализации.
- Если владелец отвечает в терминале, пока карточка открыта, карточку снимает событие `PostToolUse`, как у разрешений.
- Карточки открываются в тех же файлах, что и работа над понятностью карточки разрешения (`2026-11-06-permission-card-clarity.md`): начинать только после того, как она влита.

## Сценарий приёмки
- Claude задаёт вопрос с двумя вариантами → на острове карточка с вопросом и двумя кнопками; нажатие «Красный» → Claude продолжает с этим ответом, в терминале диалога не было.
- Два вопроса подряд в одном вызове → «1 из 2», затем «2 из 2», после последнего Claude получает оба ответа.
- Множественный выбор → отметить два варианта, «Готово» → Claude получает оба.
- «Открыть в Ghostty» → нужная вкладка выходит вперёд, диалог в терминале ждёт; «Позже» → карточка уходит, диалог ждёт.
- Вопрос ответили в терминале, пока карточка открыта → карточка исчезла сама.
