# topbar: окно острова — часть 2 (сделано)

Часть 1 (`2026-11-04-topbar-core-bridge.md`) дала ядро и мост. Эта часть — то, что видно на экране.
Написана по ходу работы, без отдельного согласования: владелец попросил сразу рабочий продукт.

## Что сделано

- `IslandPresenter` (ядро, с тестами): режим острова (скрыт / свёрнут / список / карточка), очередь карточек,
  клик по строке «ждёт» открывает карточки сессии, сводка «1 ждёт · 1 готово · 2 работает», `WatchPolicy`
  («владелец смотрит»: активное приложение совпадает с хостом сессии), `SettingsFile` (запись с сохранением
  симлинка и прав).
- Приложение `topbar` (`Sources/topbar`): прозрачное окно у выреза встроенного экрана (`NotchGeometry`),
  три вида (свёрнутый с «ушами», список, карточка с полной командой), иконка в строке меню (статус хуков,
  установка и удаление с показом разницы, «Запускать при входе», «Звук», «Выйти»), звук при «готово»,
  переход к сессии (Ghostty — приложение на передний план, VS Code — окно проекта), закрытие карточек при
  сне и пропаже выреза, предложение подключить хуки при первом запуске.
- Сборка: `scripts/build-app.sh [--install]` → `build/topbar.app` (мост хука лежит внутри), подпись ad-hoc.

## Проверено

97 юнит-тестов; приложение запущено на встроенном экране, настоящие события пропущены через настоящий мост:
вид свёрнутого острова, список, карточка; синтетический клик по «Разрешить» вернул мосту решение `allow`, карточка
закрылась. Раскладка проверена скриншотами.

## Не проверено вручную

Установка хуков из меню в настоящий `~/.claude/settings.json` (логика установщика покрыта тестами, диалог — нет),
автозапуск при входе (нужна установка приложения в «Программы»), VS Code и расширение, звук на слух,
поведение при отключении монитора и сне.

## Отладочные флаги приложения

`--skip-onboarding` (не предлагать хуки), `--debug` (печатать состояние в stderr), `--debug-open-list` (сразу
раскрыть список), `--debug-not-watching` (считать, что владелец ни на что не смотрит).

## Точность и производительность (2026-11-05)

**Точность.** Ghostty управляется через его AppleScript-словарь (разрешение «Автоматизация» спрашивается один раз при запуске, не на главном
потоке): «владелец смотрит» теперь значит «в фокусе терминал этой сессии» (сравнивается `tty` сессии и `tty` терминала в фокусе), а клик по строке
и «Перейти к сессии» переносят в нужную вкладку и окно. Пока разрешения нет, всё работает как раньше — по приложению. VS Code остаётся
приблизительным (окно проекта).

**Производительность** (изолированный экземпляр приложения, нагрузка отдельным генератором событий; CPU — среднее по интервалу):

| Сценарий | До | После |
| :- | :- | :- |
| нет сессий | 0,0 % | 0,0 % |
| три сессии и мигающий «ждёт», без потока событий | 2,9 % | 0,0 % |
| поток ~50 событий/с | 9,9 % | 2,4 % |
| память | 49 МБ | 45 МБ |

Что сделано: мигание точки «ждёт» рисует Core Animation, а не SwiftUI (давало ~3 % процессора всё время ожидания); хаб не сообщает интерфейсу о
событиях, которые ничего не меняют на экране (`PostToolUse` и пр.); интерфейс перерисовывается не чаще раза в 40 мс и только когда изменилось то,
что видно в текущем режиме (в свёрнутом виде — только сводка); размеры считаются один раз на изменение; решение «раскрывать ли остров» принимается
асинхронно и не блокирует хаб; таймер проверки живости с запасом на группировку пробуждений; мост — около 6 мс на событие (замер: 50 запусков за 0,44 с).

Известное: ad-hoc подпись меняется при каждой пересборке, поэтому система может спросить разрешение «Автоматизация» заново; стабильная подпись
появится вместе с сертификатом разработчика.
