# Качество кода

## Против привычек по умолчанию

- Без преждевременных абстракций: три похожие строки лучше помощника, которым пользуются один раз.
- Не добавлять возможностей и улучшений сверх просьбы.
- Чиня ошибку, не переделывать соседний код.
- Без мёртвого кода и закомментированных блоков: история есть в git.
- Комментарий объясняет «почему», а не «что», и пишется по-русски, как во всём коде. Нужен комментарий «что» — лучше переименовать.
- `///` — у публичного API `TopbarCore` и там, где поведение неочевидно, а не у каждой внутренней функции.

## Имена

- Swift — по Swift API Design Guidelines: типы `UpperCamelCase`, всё остальное, включая константы, `lowerCamelCase`. Один основной тип на файл, файл назван по нему (`MenuBarListController.swift`).
- `URL` — заглавными (`baseURL`, `feedbackURL`), `Id` — как слово (`sessionId`, `bundleId`). Другие сокращения — только общеизвестные.
- Булевы — с `is` / `has` / `should` / `can`.
- `server/` (TypeScript): файлы `lowercase.ts`, функции и переменные `camelCase`, типы и классы `PascalCase`, только именованные экспорты.

## Метки в коде

`TODO: что и почему` — запланированное; `FIXME: что` — известная ошибка; `HACK: что и как сделать правильно` — обходной путь. Никаких `XXX`, `TEMP`, `REMOVEME`.
